# Smriti (स्मृति) — STAGE 3 Frontend Architecture & Implementation Summary

## 1. Executive Summary

Stage 3 delivers the complete, production-grade frontend for **Smriti (स्मृति)** — an Elderly Care & Medication Management Platform designed specifically for Indian families and healthcare workflows. 

The application is implemented as a **unified Next.js App Router project** with zero TypeScript errors (`tsc --noEmit`), zero build errors (`next build`), and 100% adherence to the Stage 1 & Stage 2 backend API contracts without requiring breaking backend changes.

### Key Architectural Pillars
1. **Platform Strategy by Role:**
   - **ELDER, CARETAKER, FAMILY (Mobile-First Installable PWA):** Engineered for 360–430px smartphone viewports with bottom navigation, generous touch targets (≥56px for primary actions), tactile feedback (Vibration API), and Web Speech API audio announcements.
   - **Desktop Testability Guarantee:** When viewed on desktop screens (>600px), `MobileShell` renders the phone experience in a centered 430px frame with a subtle border and shadow on a warm `paper-2` background, alongside a contextual brand card on ultra-wide screens. Bottom navigation stays anchored inside the 430px column.
   - **DOCTOR (Web-First Desktop Ledger):** High-density split-view workspace taking advantage of full desktop screen width, collapsing gracefully into an accordion list-to-detail flow on mobile devices.
2. **True Indian Vernacular First:**
   - Spoken, respectful Hindi (हिन्दी) and Marathi (मराठी) alongside Indian English.
   - Switchable at any time from header pills or settings without URL prefix disruption (`/elder/today` remains `/elder/today`).
   - Persisted via cookie (`NEXT_LOCALE`) and synchronized to the user's backend profile (`PATCH /api/me`).
3. **Calm Heritage Editorial Aesthetic:**
   - No generic blue SaaS templates, no cartoon illustrations, no playful emoji icons.
   - Palette rooted in warm paper (`#FAF5EA`), forest green (`#1F5C4A`), turmeric saffron (`#E39B2B`), deep ink (`#1E2B25`), and muted rule lines (`#E2D8C3`).
   - Typographic hierarchy using **Mukta** for natural Devanagari/Latin UI copy, **Fraunces** for warm display numerals, and **Noto Serif Devanagari** for dignified headings.
4. **Resilient PWA & Offline Experience:**
   - Standalone `manifest.webmanifest` with multi-density icons generated via canvas (`192x192`, `512x512`, `maskable-512`, `apple-touch-icon-180`).
   - Hand-written `public/sw.js` registered strictly in production (`NODE_ENV === "production"`).
   - Strict privacy & freshness model: Static assets (`/_next/static`, icons, fonts) are cached; medical data and all `/api/*` endpoints are **NETWORK-ONLY**. Navigations failing offline render a dedicated multilingual offline fallback screen (`/offline`).

## 3. Design Tokens & Styling Architecture

The styling system is configured in `tailwind.config.ts` and `src/app/globals.css`:

### Color Palette & Semantic Tokens
```css
--paper:      #FAF5EA; /* Calming warm background */
--paper-2:    #F3EBDA; /* Secondary backdrop / desktop frame surround */
--surface:    #FFFDF7; /* Card and sheet backgrounds */
--ink:        #1E2B25; /* High contrast body text (WCAG AAA on surface) */
--ink-muted:  #5B665F; /* Secondary text and captions */
--line:       #E2D8C3; /* Hairline borders and dividers */
--forest:     #1F5C4A; /* Primary brand color (actions, buttons, headers) */
--forest-hover: #17483A;
--forest-light: #E8F1EC; /* Selected states and pills */
--saffron:    #E39B2B; /* Accent color (Next dose, warnings, pending) */
--saffron-light: #FAF2E3;
--ok:         #2F7D4F; /* Successful adherence, taken doses */
--ok-light:   #EAF4EE;
--brick:      #B93A2B; /* Missed doses, urgent notes, high risk */
--brick-light:#F9ECEB;
```

### Accessibility & Contrast Standards
- **Contrast Ratios:** All body text meets WCAG AA standards (≥ 4.5:1). Major buttons use `#1F5C4A` or `#1E2B25` with pure white `#FFFFFF` text (exceeding 7.8:1 contrast).
- **Touch Ergonomics:** All primary interactive elements on mobile (such as "मैंने ले ली" or "Given") have a minimum touch target height of **56px**, preventing accidental taps for shaky hands.
- **Large Text Mode:** Configured via `data-text-size="large"` on `<body>`. Root font size scales by +20% (`19.2px`), allowing all `rem`-based typography to enlarge harmoniously while maintaining layout containment.
- **No Reliance on Color Alone:** Doses and notifications pair color chips with explicit iconography (Check, AlertTriangle, Clock, X) and localized textual state labels ("Taken", "Missed", "Pending").

## 4. Component Architecture

All components reside in `src/components/` and are organized by scope:

### Shared Core Components (`src/components/shared/`)
1. **`MobileShell`:**
   - Detects viewport width.
   - On screens `<= 600px`: Renders 100% width and full viewport height with safe area insets (`pt-safe`, `pb-safe`).
   - On screens `> 600px`: Centered column fixed at `max-w-[430px]` with `border border-line shadow-2xl rounded-2xl overflow-hidden`.
   - On screens `> 1024px`: Displays an elegant side brand card explaining the active mobile role and providing quick links to switch roles.
2. **`DesktopShell`:**
   - High-density top bar displaying the clinic name, current date, active doctor profile, unread notification count, and language switcher.
   - Collapsible desktop sidebar with navigation items, badge counters, and direct action shortcuts.
   - Renders a responsive slide-out drawer on tablet/mobile screens.
3. **`BottomNav`:**
   - Role-aware bottom bar fixed inside `MobileShell`.
   - Supports 4 tabs for Elder (`today`, `medicines`, `appointments`, `me`), 4 tabs for Caretaker (`today`, `medicines`, `notes`, `me`), and 3 tabs for Family (`home`, `link`, `me`).
   - Clear active state indicator with saffron dot and bold font weight.
4. **`BottomSheet`:**
   - Accessible slide-up modal with tactile grab handle, smooth backdrop blur, keyboard ESC dismissal, and click-outside handling.
   - Used for dose actions, skip reason submission, invite code generation, and quick-add forms.
5. **`StatusBadge`:**
   - Renders semantic status pills (`ok`, `pending`, `missed`, `urgent`, `warning`, `neutral`) with appropriate contrast, localized text, and subtle icons.
6. **`EmptyState`:**
   - Clean, dignified placeholder with geometric diya/leaf vector motif, title, description, and optional call-to-action button.
7. **`InstallPrompt`:**
   - Intercepts `beforeinstallprompt` on Android Chrome to trigger native 1-tap installation.
   - Automatically detects iOS Safari and presents a gentle 2-step visual guide ("Tap Share -> Add to Home Screen").
   - Hides itself permanently once running in standalone PWA mode.
8. **`InviteCodeCard`:**
   - Formats 9-character passcodes (`XXXX-XXXX`) in high-contrast monospaced Fraunces font with 1-click copy to clipboard and pre-composed WhatsApp share button.
9. **`LanguageSwitcher`:**
   - Dropdown or pill selector allowing instant switching between English, हिन्दी, and मराठी.

## 6. Multilingual & PWA Implementation Details

### Multilingual Translation Engine
- Utilizes `next-intl` with a client provider architecture (`src/lib/i18n-provider.tsx`).
- Translations are structured under `src/messages/{en,hi,mr}.json`.
- Zero route clutter: Routes are not prefixed with `/en/` or `/hi/`. Instead, language selection is managed cleanly via:
  1. `NEXT_LOCALE` cookie (checked during initial mount).
  2. Browser `navigator.language` fallback.
  3. Seamless background update via `PATCH /api/me` when logged in.
- Covers 100% of UI labels, button states, error messages (including all 17 backend error codes like `DOSE_ALREADY_MARKED`, `INVALID_INVITE_CODE`, `AI_UNAVAILABLE`), and accessibility hints.

### PWA & Service Worker Strategy
- **Web App Manifest (`public/manifest.webmanifest`):**
  - Configured with `display: "standalone"`, `orientation: "any"`, and theme color `#FAF5EA`.
  - Icon set generated via `scripts/generate-icons.mjs` using high-resolution geometric SVG brand graphics.
- **Service Worker (`public/sw.js`):**
  - Hand-written, dependency-free vanilla Service Worker.
  - Registered client-side via `PwaRegister.tsx` **only in production** (`process.env.NODE_ENV === "production"`) to avoid interfering with local development.
  - **Cache Strategy:**
    - Static assets (`/_next/static/*`, `/icons/*`, `/manifest.webmanifest`): Cache-first with stale-while-revalidate.
    - Medical data & APIs (`/api/*`): Strict **NETWORK-ONLY**. Medical information is never stale-cached for patient safety.
    - Page navigations: Network-first. If network fails and request is an HTML navigation, serves the localized `/offline` page.

## 7. Assumptions & Minor Non-breaking Refactors

### Backend Adjustments Made
During the build, zero backend API endpoints, database schemas, or permission policies were altered. Exactly one mechanical refactor was applied for Next.js App Router route safety:
- **`src/app/api/doctor/brief/route.ts` Refactor:**
  - Next.js 15 App Router strictly enforces that route files (`route.ts`) export only valid HTTP method handlers (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS`).
  - The helper function `generateOrFetchDailyBrief` had been exported directly from `src/app/api/doctor/brief/route.ts`, causing Next.js route type validation to fail during `next build`.
  - **Fix:** Moved `generateOrFetchDailyBrief` to `src/lib/ai/daily-brief.ts` and updated callers (`route.ts`, `refresh/route.ts`, `cron/daily/route.ts`). Zero logic was changed.

### Production Assumptions
1. **Demo Mode Credentials:** Provided in `.env.example` as `NEXT_PUBLIC_DEMO_*` for quick 1-tap judging evaluation without requiring manual typing.
2. **Web Speech API:** Leverages standard browser `window.speechSynthesis`. Supported natively in Chromium, Android Chrome, and Safari. Fallbacks gracefully if voice synthesis is unavailable.
3. **Vibration API:** Leverages `navigator.vibrate([100, 50, 100])` for dose confirmation. Fails silently on devices without haptic motors (e.g. desktop browsers).
4. **Offline Mode:** In compliance with health data privacy and freshness requirements, medical dosages are not stored in unencrypted client IndexedDB caches; instead, the offline screen clearly explains connectivity loss and prompts the user to reconnect.
